# Milestone 4 investigation interface and ownership

Lead-defined before delegation on 30 October 2026. This milestone adds one deterministic descriptive detector and does not alter ingestion, the processed contract, or the Neo4j model. Earlier milestone scope restrictions are historical; this document scopes milestone 4 only.

## Ownership

- Agent 1 owns only `scripts/investigation.py` and `scripts/investigate_batch.py`: engine, input preparation, pure scoring, JSON CLI.
- Agent 2 owns only `tests/test_investigation.py` and `tests/test_investigation_integration.py`: independent fixtures, method and real-instance tests.
- Lead owns this interface, `docs/investigation_validation.md`, README, evidence under `docs/evidence/investigation/`, integration and actual execution. Coordinate shared-interface changes with lead before editing.
- Two agents only, no additional agents. No edits to existing ingestion/graph/config/dependencies. Stdlib, existing PyArrow and Neo4j driver suffice. No original archive reads, Docker work, detector additions, Streamlit/LLM/causal/quality work or graph writes from the engine.

## Frozen method and compatibility

Detector ID `elapsed_tick_peer_median_mad`, version `1.0.0`, result schema version 1. Default selected variables, in stable order: `aeration_rate`, `sugar_feed_rate`, `ph`, `temperature`. These are documented continuous process_value channels with reported-only units and no sparse offline measurements. No selection using annotations, excursions, harvest outcomes or raw flag fields. Variable configuration may select a nonempty subset of these four; do not add other fields in this milestone.

At each target tick, use finite peer values at exactly the same integer elapsed-time tick. Median `m = median(x_peer)`, raw MAD `median(abs(x_peer - m))`, reference spread `s = 1.4826 * MAD`, point deviation score `abs(x_target-m)/s`. Default `min_peers=10`, `threshold=6.0`, `min_consecutive=5`; strictly `score > threshold` exceeds. The scale factor is fixed/versioned, not tuned. Threshold is a configurable statistical heuristic, not a probability, operating limit or quality specification. At 0.2 h spacing, five observations span 0.8 h between their endpoints.

Reference selection uses only graph-available batch membership, observed data availability/overlapping elapsed-time ranges and the existing Parquet `control_regime` compatibility metadata. Known groups: recipe_driven (published 1–30), operator_controlled (31–60), apc_raman (61–90). The exact published batch ranges already underpin ingestion's metadata; use that metadata strictly for grouping, never as process features. `not_documented` / unknown groups are NOT compatible with each other; report all variables skipped with `undocumented_process_compatibility`. Target always excluded, even if explicitly requested as a peer. Configurable `peer_batch_ids` can restrict membership but cannot override compatibility; record final membership and exclusions. Unknown requested peer IDs fail clearly. No annotation reads or global graph-integrity call in the detector path: deleting graph annotations must not affect it.

Missing/nonfinite target values: skip tick and break runs. Null/nonfinite peers: omit that value, record finite coverage. No peer rows at a tick: `unmatched_tick`; peer rows but too few finite values: `insufficient_peers`. Coverage is variable/tick-specific, never forward-filled. Zero MAD: target exactly equal to median -> score 0 / `zero_mad_equal`, no exceedance; otherwise score null / `zero_mad_unscorable`, break run. Never add epsilon/floor, infinity, interpolation, extrapolation or imputation. Production bundle validation already rejects unexpected nonfinite inputs; pure tests may exercise them explicitly. Reject duplicate sample ticks and invalid coordinate types rather than coerce.

Group exceedances into consecutive integer-tick runs of the same direction (above/below median). Gaps, missing/unscorable points, nonexceedances and direction changes break runs. Retain runs with at least min_consecutive. Interval `statistical_deviation_score` is the arithmetic mean of point deviation scores; retain peak score separately. Rank descending mean, descending peak, then configured variable order, then start tick for deterministic ties. No accuracy/severity/root-cause interpretation.

## Python interfaces

`scripts.investigation.DetectorConfig` is a frozen dataclass with `variables=DEFAULT_VARIABLES` (tuple of strings), `min_peers=10`, `threshold=6.0`, `min_consecutive=5`, `peer_batch_ids=None` (optional tuple of stable batch IDs). Validate types strictly; positive finite threshold, min_peers>=2, min_consecutive>=1, variables allowlisted and unique, peer IDs nonempty unique strings. Normalize deterministic ordering for restricted peers. `config=None` means default configuration.

`score_variable(target_measurements, peer_measurements, config=None)` is pure and accepts a list of target measurement dicts and a dict `{peer_batch_id: list[measurement dict]}`. Minimal records: batch_id, sample_id, time_tick, time_h, value, source_file_id, source_row_number. No annotation or campaign fields. Exclude the target batch even if present in peer_measurements. Sort ticks and peer IDs deterministically. Return a JSON-compatible dict with:
- `points`: per-target-tick records with original target measurement identity/source coordinates, `observed_value`, `reference_median`, `reference_mad`, `reference_spread`, `deviation_score`, `peer_count`, sorted `peer_batch_ids`, `status`, `exceeds`, and `direction` (above/below/equal or null). Keep finite peer support measurements so evidence is reproducible.
- `intervals`: start_tick, end_tick, start_time_h, end_time_h, direction, point_count, statistical_deviation_score, peak_deviation_score and `evidence` (all retained point records).
- `skipped_tick_counts`: reason counts. Agent 1 may add useful count/diagnostic fields; coordinate any named-field changes with Agent 2.

`investigate_batch(driver, batch_id, processed_dir=graph.DEFAULT_OUTPUT, database='neo4j', config=None, contract_path=graph.DEFAULT_CONTRACT)` returns one deterministic result dict. Require exact stable batch ID, derive dataset identity from the validated bundle rather than split untrusted strings. Use existing graph.list_batches, graph.list_variables and graph.batch_variables/get_reference, with complete/model guards, to resolve target, peers, variable availability and artifact/source provenance. Every used reference must equal the authoritative reference reconstructed from the already validated bundle. Reuse graph.validate_processed and graph._local_reference to avoid revalidating all files per peer/variable; this does not change graph APIs. Validate once, restrict numerical projection to identity/time/source and selected process fields; compatibility projection contains only batch_id/batch_ref/control_regime. Never call graph.published_annotations or check_graph_integrity, and never supply label/raw metadata/harvest fields to scoring. Full-bundle integrity validation remains the existing graph validator's responsibility, separate from detector feature selection.

Check graph batch identities/count/time metadata against local tables, pin all reference dataset/manifest/cache/artifact/source metadata. Missing/unavailable selected variable can be skipped with explicit reason; mismatched versions or graph references fail rather than fall back to local guesses. No repeated graph writes, model changes or new nodes. Recheck pinned manifest and output hashes before return to reject concurrent bundle changes. Sorting, peer restrictions, findings IDs and all floats must be deterministic. No run timestamp, random ID, absolute machine path or timing in the result.

## Result schema (stable top-level names)

- `schema_version: 1`, `record_kind: derived_investigation`, `detector` with ID/version/method and score description.
- `dataset` with dataset_id, graph_model_version, manifest_sha256, cache_key and processed artifact identities/checksums (all three artifacts can be included).
- `batch` with graph-resolved batch_id/ref and observed sample/time bounds; no published fault fields.
- `configuration` with all effective config fields, fixed MAD factor, cohort policy and zero-MAD/missing-data rules as useful.
- `reference_cohort` with compatibility_group, membership (`members` sorted list containing batch_id/ref), exclusions/reasons, explicit target exclusion and compatibility metadata provenance. Per-variable/per-tick finite membership must also be recoverable from evidence points.
- `variable_results` stable configured order, each including variable/output_column, variable_id, target graph `reference`, status (analyzed/skipped), skipped_reason, coverage/point counts, skipped_tick_counts, explicit skipped ticks/reasons (compact diagnostics are acceptable), and peer references or a shared mapping for reproducibility. Distinguish no findings from no scoreable data.
- `findings`: ranked retained interval dicts decorated with variable, variable_id, batch_id, stable deterministic finding_id, `record_kind: derived_statistical_deviation`, target reference, score, observed/reference evidence points. Each target and finite peer support measurement must retain source file/row; common source-column index/header/member/archive/artifact identity may be bound by each variable's graph reference. Preserve distinction between published measurement evidence and derived medians/scores; do not relabel simulations as physical plant observations.
- `limitations`: explicit deterministic strings about cohort compatibility limits, peer contamination, elapsed-time phase alignment, no calibrated accuracy, MAD/coverage skips, selection limited to four channels, source units/simulation scope and no causal/quality interpretation.

CLI: `.venv/bin/python scripts/investigate_batch.py --batch-id ID --output PATH [--processed-dir PATH] [--min-peers N] [--threshold X] [--min-consecutive N] [--variable NAME ...] [--peer-batch-id ID ...]`. Require --output, write sorted-key UTF-8 JSON with newline and allow_nan=False; atomic temp-file+replace, no partial output on errors. Do not permit output to overwrite validated manifest/Parquet/source/contract files. Credentials use existing environment helpers; errors JSON/nonzero and redact credentials. Do not include output path/timestamp in deterministic result; stdout may be the same JSON or a compact status. No credentials written to result.

Actually change and remove graph annotations and assert identical engine result; never mutate production annotations.
